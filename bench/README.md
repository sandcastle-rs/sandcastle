# Benchmark: sandcastle vs BuildKit

Manual benchmark; nothing here runs in CI.

## What it measures

Wall-clock time of `sandcastle build` and `buildctl build` (BuildKit, in a container) producing an OCI layout, timed with hyperfine. Base images come from a local registry on `localhost:5001`, so registry latency is excluded.

Cases (`bench/cases/`):

- `alpine-apk`: one `RUN apk add` of curl, git and jq.
- `debian-apt`: one `RUN apt-get install` of ca-certificates, curl and git.
- `go-build`: `COPY` a small Go module and `go build` it in the golang image.
- `many-runs`: 50 trivial `RUN` steps.
- `large-copy`: `COPY` of about 140 MiB in 10,020 files (generated by `bench/gen-context.sh`).

Modes:

- `cold`: sandcastle runs with an empty `SANDCASTLE_ROOT` (no image store, no cache); BuildKit runs with a fresh daemon and an empty state volume.
- `warm`: one warmup run, then timed runs reusing the sandcastle store and the BuildKit state volume. BuildKit is restarted before each run (untimed) and still runs with `--no-cache`, so only content such as base image layers is warm.

The package cases download from the internet in every run, so they include network time.

## macOS setup

1. `brew install hyperfine buildkit skopeo`
2. Start a podman machine: `podman machine start`. For the rootful BuildKit mode the machine must be rootful (`podman machine set --rootful`, while stopped). If rootful BuildKit does not run there, use `--tools sandcastle,buildkit-rootless`.
3. `bench/registry.sh start && bench/registry.sh seed`
4. `just bench` (runs `just build` first). Arguments are passed through, for example `just bench --cases many-runs --runs 3`.

The registry uses port 5001 because macOS AirPlay Receiver occupies 5000.

`ENGINE` selects the container engine (`docker` or `podman`); default is `podman` on macOS and `docker` on Linux.

skopeo reads `bench/registries.conf` (a minimal v2 file) through `CONTAINERS_REGISTRIES_CONF`, so a stale system `registries.conf` does not break seeding. Set the variable yourself to override.

## Linux (Hetzner dedicated) setup

Run `bench/setup-ubuntu.sh`, then seed and run as above. To compare both BuildKit flavours:

```
bench/run.sh --tools sandcastle,buildkit,buildkit-rootless
```

## Troubleshooting

`bench/lib.sh` sets `REGISTRY_AUTH_FILE` to `bench/auth.json` (empty) so a broken credential helper in your own container auth config cannot fail the anonymous pulls. Set the variable yourself to override.

## Reading results

Each run writes `bench/results/<stamp>/<case>-<mode>.md` (hyperfine table), the matching `.json`, and `environment.md`. Results are git-ignored; commit a run you want to keep with `git add -f bench/results/<stamp>`.

## Cleanup

```
bench/buildkit.sh stop; bench/registry.sh stop
```
